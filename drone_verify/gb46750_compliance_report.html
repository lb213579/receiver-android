四、结论

⛔ 接收到的信号不符合 GB 46750-2025 规范要求。

依据如下：

  • §5.2.1：运行识别信息数据包应包含数据类型、版本号、数据标识和数据内容项；本次仅收到 全零 Basic ID 空帧（idType=0、uaType=0、UAS ID 为空），不含任何有效数据内容项。
  • §5.2.3 表2：17 个必选(M)数据项（唯一产品识别码、实名登记标志、无人机位置、航迹角、地速、大地高度、运行状态、坐标系类型、水平/垂直/速度精度、时间戳、时间戳精度、飞手位置/高度/位置类型、无人机分类）中，唯一产品识别码虽在 Basic ID 中但为空，其余 16 项因缺失 Location/System/Operator ID 报文而完全缺失。必选项全部不符合。
  • §5.1.2 / §5.1.3：合规无人机应在动力移动全过程持续、自动（间隔≤1s）发送运行识别信息且不可关闭；当前信号无法构成持续有效的运行识别。
  • §6.1.2：传输方式标记为 BT4（蓝牙4.x），需核实是否满足"蓝牙5.0及以上或Wi-Fi"的链路要求（见第二节）。

判定：该信号不可能是合规民用无人机发出的有效运行识别信息。最可能来源为：未配置的 RID 模块 / 测试信标 / 开发板，或伪造、异常广播。请切勿据此识别或信任任何真实无人机。

注：GB 46750-2025 自身定义了独立的数据包格式（§5.2.1 图3 / 表1），而 OpenDroneID App 解码的是 ASTM F3411 蓝牙/Wi-Fi 广播。两者在编码（如时间戳：ASTM 为2字节秒，GB 为6字节Unix毫秒）与部分字段（分类、坐标系类型）上存在差异，故表中标记"无 1:1 对应"的项需由 GB 自有报文/扩展承载；无论如何，本次所有必选内容项均未收到。
